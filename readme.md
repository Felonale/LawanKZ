# LawanKZ — анализ нормативных правовых актов Казахстана

## Учебная работа: недели 1–6

Cобран корпус из 6 русскоязычных НПА (62 467 слов), реализованы очистка, морфологический разбор, сравнение лемм и стемов, BoW и TF‑IDF по 325 статьям. Затем обучены Word2Vec, fastText и учебная реализация GloVe, построены PCA-визуализация и прототип поиска похожих статей. Это выполняет альтернативное требование по объёму **50 000+ слов**, но не требование **500–1000 отдельных документов**.

Воспроизведение из PowerShell (Python 3.13):

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-week4.txt
.\.venv\Scripts\python.exe .\scripts\build_corpus.py
.\.venv\Scripts\python.exe .\scripts\run_weeks_1_4.py
.\.venv\Scripts\python.exe .\scripts\run_weeks_5_6.py
.\.venv\Scripts\python.exe -m jupyter lab .\notebooks
```

Поиск после обучения:

```powershell
.\.venv\Scripts\python.exe .\scripts\search_similar.py "риски системы искусственного интеллекта" --top 5
```

`build_corpus.py` использует сохранённые страницы из `data/raw/`; при их отсутствии получает их заново из «Әділет», поэтому результаты могут измениться с новой редакцией актов. Проект не даёт юридических консультаций. Для проверок: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`.

## Описание

Учебный NLP-проект для автоматизированного извлечения ключевой информации и поиска семантически похожих нормативных правовых актов (НПА) Республики Казахстан.

Рабочая область первой версии: русскоязычные НПА по персональным данным и информационной безопасности. Документы об искусственном интеллекте включаются, если относятся к этой области. Проект не выдает юридические консультации.

Основной пользовательский сценарий: пользователь выбирает документ или вставляет его фрагмент, а система находит похожие документы и положения, показывает оценку сходства и объясняет результат с помощью общих ключевых терминов и найденных нормативных требований.

Подробная постановка задачи, гипотеза, границы MVP, схема эксперимента и критерии готовности описаны в [docs/problem_statement.md](docs/problem_statement.md).

## Технологии

- **Python 3.13** — основной язык;
- **HTTPX + Beautiful Soup** — получение и разбор документов, если официальный источник не предоставляет удобный структурированный формат;
- **pandas** — таблицы с текстами, метаданными и результатами экспериментов;
- **spaCy** с русскоязычной моделью — токенизация и лемматизация;
- **scikit-learn** — TF–IDF, косинусное сходство и метрики;
- **Sentence Transformers** — готовые текстовые эмбеддинги и семантический поиск;
- **Streamlit** — демонстрационный веб-интерфейс;
- **pytest** — автоматические тесты.

Обоснование выбора и разделение обязательных и дополнительных библиотек приведены в разделе «Технологический стек» подробной постановки.

## Первый прототип: разбор TXT-файла

Добавлен небольшой работающий прототип для первого этапа разработки. Он читает русскоязычный файл UTF-8, выделяет заголовки вида `Статья 1. Название`, разбивает текст на предложения с помощью spaCy и отмечает предложения с явными словами `обязан`, `должен`, `вправе`, `не допускается`, `запрещается`, `подлежит`. Результат можно вывести в JSON или в читаемый Markdown. Для проверки есть [вымышленный учебный текст](examples/synthetic_act.txt) и [пример отчёта](examples/synthetic_act.report.md); учебный текст **не является действующим НПА**.

Запуск из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m lawankz .\examples\synthetic_act.txt
```

Сохранение результата в файл:

```powershell
.\.venv\Scripts\python.exe -m lawankz .\examples\synthetic_act.txt --output .\analysis.json
```

Сохранение читаемого Markdown-отчёта:

```powershell
.\.venv\Scripts\python.exe -m lawankz .\examples\synthetic_act.txt --output .\analysis.md
```

Преобразовать JSON в Markdown:

```powershell
.\.venv\Scripts\python.exe -m lawankz.markdown .\analysis.json --output .\analysis.md
```

Без `--output` результат печатается в терминал. Формат можно также указать: `--format md` или `--format json`.

Проверка:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для запуска нужны `spacy` и модель `ru_core_news_sm`. При создании нового окружения используйте Python 3.13, затем установите их:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install "spacy>=3.8,<3.9"
.\.venv\Scripts\python.exe -m spacy download ru_core_news_sm
```

Ограничения этого **первого TXT-прототипа**: он использует простые языковые правила, а не юридический анализ. Он может пропускать требования без указанных слов и ошибочно отмечать предложения, где такие слова встречаются в другом контексте. Отдельный конвейер недель 1–4 уже загружает официальные НПА и строит статистические матрицы, но поиск сходства и юридическая верификация в него пока не входят.

## План

| Этап | Что делаем | Результат |
| ----- | --------------------------------------- | --------------------------------------- |
| **1** | Формулируем задачу | цель, объект, предмет, гипотеза — **готово** |
| **2** | Собираем корпус | 100–200 НПА |
| **3** | Очищаем документы | подготовленный корпус; первый прототип разбиения TXT готов |
| **4** | Выполняем лингвистическую обработку | токены, леммы, n-граммы |
| **5** | Извлекаем ключевые термины и требования | NLP-модуль |
| **6** | Строим similarity | поиск похожих НПА |
| **7** | Оцениваем качество | Precision@5, nDCG@5, MRR, F1 + сравнение методов |
| **8** | Создаём Streamlit-интерфейс | готовая демонстрационная система |

## Не входит в первую версию

- генерация юридических консультаций;
- чат с законами;
- полноценный RAG;
- обучение собственного BERT;
- автоматический анализ вообще всех НПА Казахстана;
- одновременная работа на русском и казахском;
- сложная юридическая онтология.
